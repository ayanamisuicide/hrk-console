# gui

Нативное GUI-окно для того же Telegram-юзербота [Heroku](https://github.com/coddrago/Heroku),
что и [`hkc`](../README.md) — отдельный Go-модуль внутри этого же репозитория,
переиспользующий `botproc`/`logfeed`/`state` из корня напрямую (через `replace`
в `go.mod`, см. [устройство проекта](../docs/architecture.md)), но вместо TUI — окно на
Wails: Go-бэкенд + вёрстка в нативном webview. Своя вёрстка, но те же
контролы (debug, порог показа, авто-перезапуск бота) и те же горячие клавиши
(`d`, `s`, `w`, `a`, `/`, `n`/`N`, `r`/`R`, `g`/`G`, `?` — справка в окне).

Раскладка: шапка с тумблерами, статус-строка (жив ли бот, счётчики проблем,
самые шумные модули, состояние связи) и лог во всю оставшуюся высоту. Всё,
что нужно не всегда, — за кликом по сегменту статус-строки: полный список
модулей выпадает списком, настройка удалённого бота открывается окном.
Постоянной боковой панели нет намеренно — лог единственное, ради чего это
окно открывают, и делить с ним ширину нечему.

Сверх того, чего нет в TUI: подсветка совпадений активного фильтра в тексте
лога, копирование строки/трейсбека по клику (⧉ при наведении),
desktop-уведомление при автоперезапуске бота (через `notify-send`,
best-effort), кнопка «Установить недостающее» на экране проверок —
открывает настоящий терминал с автонастройкой окружения бота (`sudo` внутри
webview спросить негде), и самообновление сразу с обоих каналов: при старте
окно опрашивает `stable` и `dev`, показывает оба с датой публикации, если
хоть один предлагает сборку новее запущенной (подробнее — [docs/usage.md
§Обновления](../docs/usage.md#обновления)); бейдж в шапке — тот же ответ, но
для повторной проверки вручную в любой момент. Клик качает и подменяет
бинарник на диске (второй клик — перезапуск), правая кнопка мыши на бейдже
просто открывает страницу релиза. Работает только для сборок из чистого
тега (`git describe` без суффикса) — `wails dev`/сборки из рабочего дерева
его не запускают вовсе.

Собирается и работает не только на Linux — Windows-сборка (`wails build
-platform windows/amd64`) умеет подключаться к боту на Linux по SSH, когда
самого бота рядом нет и быть не может (см. [docs/usage.md §Бот на другой
машине](../docs/usage.md#бот-на-другой-машине)); экран проверок на
не-Linux вместо восьми локальных проверок сразу показывает подсказку
подключиться так.

Бот по умолчанию ищется в `~/Heroku`, каталог переопределяется переменной
`HEROKU_DIR` — как и у `hkc`.

## Зависимости

Разово, помимо Go:

```sh
sudo apt install libgtk-3-dev libwebkit2gtk-4.1-dev build-essential pkg-config nodejs npm
go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

`wails` встанет в `$(go env GOPATH)/bin` — этого каталога обычно нет в `PATH`,
поэтому либо добавьте его туда, либо зовите по полному пути (так делает
`make gui`).

## Установка как приложение

Из корня репозитория — как и `make gui` ниже:

```sh
./gui/install.sh
```

Соберёт и положит бинарник в `~/.local/bin`, иконку — в тему значков, ярлык —
в меню приложений и на рабочий стол. Без `sudo`: всё в домашнем каталоге.
Удалить — `./gui/install.sh --uninstall`.

Либо через общую точку входа, которая сама соберёт то, что ещё не собрано:

```sh
./launch.sh
```

и выбрать «Приложение (GUI)».

## Сборка

Только собрать, без установки, из корня репозитория:

```sh
make gui
```

Или вручную, отсюда:

```sh
wails build -tags webkit2_41
```

Тег обязателен: на Ubuntu/Mint 24.04 доступен только `webkit2gtk-4.1` (пакета
`-4.0` в репозиториях больше нет), а Wails по умолчанию ищет `-4.0`.

Бинарник — `build/bin/hrk-console-gui`.

## Разработка

`wails dev` — Vite hot-reload фронтенда + доступ к Go-методам из devtools на
`http://localhost:34115`.
