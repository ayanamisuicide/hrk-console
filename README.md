# heroku-console

Консоль для Telegram-юзербота [Heroku](https://github.com/coddrago/Heroku): запуск, остановка и живой просмотр логов из терминала.

```
╭─ HEROKU ──────────┬──────────────────────────── ● live  2.2.2  ·  1ч 12м ─╮
                    │
 М О Д У Л И        │ 00:13:01  INF   terminal   Command .sh executed by 827…
 tl_cache █████  12 │ 00:13:04  WRN   spotify    Token refresh took 4.2s
 spotify  ███▎    5 │ 00:13:07  ERR   tl_cache   Failed to resolve @unknown  ×12
 terminal █▋      2 │                          ↳ PeerIdInvalidError: could not…
                    │ 00:13:20  INF   spotify    now playing: Radiohead — Creep
 П О Т О К          │
 ▁▂▅▇▃▁▁▂▆▃▁▁▂▃▁▂▁▁ │
                    │
 П Р О Б Л Е М Ы    │
 ⚠ 3   ✗ 12         │
 ● live             │
 pid 4821           │
 1ч 12м             │
╰───────────────────┴──────────────────── debug: скрыт · ? справка · q выход ─╯
```

Экран разделён по вопросам, на которые отвечает. **Лог справа** — что именно случилось. **Панель слева** — кто сейчас шумит, где копятся ошибки, жив ли процесс: столбик модуля красится по худшему, что у него было, так что красная полоса сразу показывает, откуда лезут ошибки. Панель прячется по `s` и сама уходит на окне уже 84 колонок — место под сообщение дороже статистики.

Уровень показывается бейджем с заливкой — `WRN` и `ERR` видно периферийным зрением, не вчитываясь. `DBG` намеренно тихий.

Подряд идущие одинаковые записи схлопываются в одну со счётчиком `×N` у правого края: одна отвалившаяся сеть больше не выдавливает с экрана всё остальное. Время показывается от последнего повтора, счётчики `⚠`/`✗` продолжают считать каждое событие.

## Зачем

Смотреть `tail -f heroku.log` глазами тяжело: в живом логе 96% строк — это `[DEBUG]` от `urllib3`, `git` и внутреннего кэша, а нужные события тонут между ними. Здесь лог разложен по колонкам, шум скрыт по умолчанию, а состояние процесса всегда перед глазами.

Лежит **вне** каталога бота намеренно: `heroku/log.py` умеет делать `reset_to_master()` и `restore_worktree()`, что может снести посторонние файлы внутри `~/Heroku`.

## Установка

Нужен [Go](https://go.dev/dl/) 1.24+ для сборки. Бот по умолчанию ищется в `~/Heroku`, каталог переопределяется переменной `HEROKU_DIR`.

```sh
git clone <этот-репозиторий> ~/heroku-console
cd ~/heroku-console
make build          # соберёт bin/hkc
./bin/hkc
```

Чтобы вызывать из любого места:

```sh
make install        # положит бинарник в ~/.local/bin/hkc
```

## Первый запуск: вход в аккаунт Telegram

Консоль умеет поднять окружение бота с нуля — склонировать репозиторий, создать `venv`, поставить зависимости, — но **войти в аккаунт Telegram вместо вас она не может**. Это разовый интерактивный шаг: Heroku при самом первом запуске спрашивает `api_id`, `api_hash`, номер телефона, код из Telegram и, если включена двухфакторка, облачный пароль. И hkc, и GUI запускают бота в фоне с выводом в файл лога, без подключённого ввода — если в этот момент бот попросит что-то ввести, ответить будет некому, и он тут же упадёт с `EOFError`. Поэтому первый вход в аккаунт нужно сделать вручную, один раз, в обычном терминале — дальше hkc и GUI управляют уже готовой сессией и это разовый шаг больше не повторяется.

### 1. Получить API_ID и API_HASH

1. Откройте [my.telegram.org/apps](https://my.telegram.org/apps) и войдите под тем номером, с которого будет работать бот.
2. Создайте приложение — название и платформа значения не имеют, вписать можно что угодно.
3. Скопируйте **App api_id** и **App api_hash**, они понадобятся на следующем шаге.

### 2. Linux Mint / Ubuntu

```sh
git clone https://github.com/coddrago/Heroku ~/Heroku
cd ~/Heroku
python3 -m venv venv          # именно venv, не .venv — под этим именем его ищут hkc и GUI
source venv/bin/activate
pip install -r requirements.txt
python3 -m heroku
```

Если `~/Heroku` уже существует — например, его сама склонировала автонастройка при первом запуске `hkc`, — просто зайдите в каталог и продолжите с `python3 -m venv venv`, `git clone` повторно не нужен.

Бот спросит `api_id`, `api_hash`, номер телефона и код из Telegram (и облачный пароль, если он у вас включён) — вводите то, что получили на шаге 1. Когда в терминале появится баннер `🪐 Heroku … started`, вход выполнен: нажмите `Ctrl+C`, чтобы остановить это разовое ручное подключение. Дальше бота запускает hkc — см. «Использование» ниже.

### 3. Windows

hkc и GUI управляют ботом только на Linux — они запускают и останавливают процесс через `bash` и читают его напрямую из `/proc`, на Windows этого просто нет. Сам бот на Python кросс-платформенный, поэтому есть два варианта:

**Вариант А — WSL (рекомендуется).** Поставьте Ubuntu через WSL (в PowerShell от администратора: `wsl --install -d Ubuntu-22.04`), а внутри неё пройдите шаг 2 целиком, как на обычном Linux. hkc и GUI, собранные и запущенные внутри той же WSL, тоже будут работать — с точки зрения Linux-подсистемы это обычный Ubuntu.

**Вариант Б — бот сам по себе, без hkc.** Тогда управлять им (запуск, остановка, перезапуск) придётся вручную, теми же командами, что и вход — консоль его не увидит и не возьмёт под присмотр:

```powershell
git clone https://github.com/coddrago/Heroku
cd Heroku
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python -m heroku
```

Дальше то же самое: `api_id`, `api_hash`, номер, код, при необходимости пароль. Остановка — `Ctrl+C` в этом же окне; чтобы запустить снова — та же команда `python -m heroku` из активированного `venv`, без повторного `git clone` и `pip install`.

## Использование

```sh
hkc              # проверки, затем меню выбора режима
hkc 2            # сразу нужный режим, без меню
hkc --no-check   # пропустить автонастройку и проверки (для вызова из скриптов)
hkc --no-setup   # пропустить только автонастройку, проверки оставить
hkc --version    # версия сборки
hkc --help       # краткая справка
```

Перед первым запуском консоль сама поднимает всё, чего не хватает: клонирует `~/Heroku` (или `HEROKU_DIR`), ставит `python3`, `ffmpeg` и эмулятор терминала для режима «два окна» через `apt-get`, создаёт `venv` и ставит зависимости бота из `requirements.txt`. Каждый шаг сначала проверяет, не сделано ли уже, — повторные запуски ничего не трогают. Отключается флагом `--no-setup`.

Отдельно доставляются зависимости **загруженных модулей**. `requirements.txt` бота про них не знает, а загрузчик ставит только то, что модуль объявил заголовком `# requires:`; модуль, который просто делает `import httpx`, падает при каждом старте с `ModuleNotFoundError`, и видно это лишь трейсбеком в логе. Консоль разбирает импорты всех файлов в `loaded_modules`, оставляет те, что не резолвятся в venv бота, и ставит их туда.

Импорты берутся из AST, а не поиском по тексту: `import` внутри строки или в комментарии не должен превращаться в попытку что-то поставить. Имена, которые загрузчик подменяет на лету (`telethon` и `hikkatl` разворачиваются в `herokutl`), пропускаются — ставить рядом с форком оригинал нельзя. Где имя импорта не совпадает с именем пакета, работает таблица перевода: `PIL` → `pillow`, `bs4` → `beautifulsoup4` и ещё десяток частых случаев. Пакеты ставятся по одному: имя выведено из импорта и может не найтись на PyPI, и одна промашка не должна утащить за собой остальные — что не встало, консоль назовёт поимённо.

Затем прогоняются проверки окружения — каталог бота, файл лога, venv, `python3`, `ffmpeg`, зависимости модулей, права на запись — и модульные тесты. Так причина «почему не работает» видна сразу, а не после пустого экрана. Отключаются флагом `--no-check` (заодно с автонастройкой).

Тесты запускаются с `-count=1`, то есть кэш результатов отключён: с кэшем `go test` возвращает `(cached)` за миллисекунды, и проверка сообщала бы «пройдены», ничего при этом не выполнив. Путь к исходникам вшивается в бинарник при `make build`, поэтому прогон работает и у установленной через `make install` консоли. Если репозитория на месте уже нет или Go не установлен, проверка честно помечается пропущенной.

`launch.sh` открывает консоль в новом окне терминала (ghostty, kitty или alacritty — что найдётся) — удобно повесить на ярлык рабочего стола.

### Ярлык

В репозитории лежит `Heroku Logs.desktop` с плейсхолдером вместо пути. Подставить свой и положить в меню приложений:

```sh
sed "s|/absolute/path/to/heroku-console|$PWD|" "Heroku Logs.desktop" \
    > ~/.local/share/applications/heroku-logs.desktop
```

Ярлык появится в меню приложений любого окружения (Cinnamon, MATE, Xfce и так далее), его можно закрепить в панели или доке. Чтобы получить ещё и иконку прямо на рабочем столе, та же команда, только с `~/Desktop` вместо `~/.local/share/applications`, и файлу нужны права на запуск:

```sh
sed "s|/absolute/path/to/heroku-console|$PWD|" "Heroku Logs.desktop" \
    > ~/Desktop/heroku-logs.desktop
chmod +x ~/Desktop/heroku-logs.desktop
```

Иконка на столе появляется не везде: работает в KDE Plasma и Xfce (там же может понадобиться через контекстное меню файла подтвердить «Разрешить запуск» при первом клике), в COSMIC и GNOME по умолчанию значков на рабочем столе нет вовсе — там ярлык доступен только через меню приложений.

| Режим | Что делает |
| --- | --- |
| 1 · Подключиться к боту | Показывает логи, не трогая процесс |
| 2 · Перезапустить бота | Останавливает и запускает заново |
| 3 · Два окна | Родная консоль бота в отдельном окне + лог в этом |
| 4 · Остановить бота | Просто `stop`, без просмотра логов |

В меню: `↑↓` или `jk` — выбор, `Enter` — запуск, `1`–`4` — сразу нужный режим, `q` — выход.

### Просмотр логов

| Клавиша | Действие |
| --- | --- |
| `d` | Показать или скрыть строки уровня `[DEBUG]` |
| `s` | Показать или скрыть панель статистики |
| `w` | Порог показа по кругу: всё → warning и выше → error и выше |
| `m` | Выбрать модуль из списка панели и отфильтровать по нему |
| `r` `R` | К следующему / предыдущему перезапуску бота |
| `/` | Живой поиск: ввести подстроку и Enter, пустой ввод снимает фильтр |
| `n` `N` | К следующей / предыдущей проблеме (warning и выше) |
| `?` | Справка по клавишам |
| `↑↓` `jk` | Прокрутка на строку |
| `PgUp` `PgDn` | Прокрутка на полэкрана |
| `g` `G` | В начало / в конец |
| колесо мыши | Прокрутка |
| `q` | Выйти из просмотра (бот продолжит работать) |

Выход из просмотра **не** останавливает бота — он живёт в своей сессии.

Прокрутка «прилипает» к низу: пока вы внизу, новые строки видны сразу; стоит подняться вверх почитать историю — позиция остаётся на месте, и лог не дёргает вас обратно.

Поиск ищет подстроку без учёта регистра по модулю и тексту сообщения. Активный фильтр виден в панели, в разделе «ФИЛЬТР» (`/spotify`).

Если лог перестал читаться — файл удалили, права поменялись — шапка честно говорит «⚠ лог не читается» и сколько это длится, а слежение само подхватывает файл, когда он возвращается. Ротацию (`heroku.log` крутится на 10 МБ) и обрезание файла переживает без потери строк.

Заголовок окна терминала показывает счётчики `⚠`/`✗`, а на новый warning или error подаётся звуковой сигнал — большинство эмуляторов подсвечивают вкладку или иконку в доке, так что пропустить проблему сложнее, даже если окно не в фокусе.

### GUI

Тот же бот, но нативное окно вместо терминала — тот же `HEROKU_DIR`, тот же лог, та же логика показа. Собирается и запускается отдельно (подробности — в [`gui/README.md`](gui/README.md)):

```sh
cd gui
wails build -tags webkit2_41   # на Ubuntu/Mint 24.04 доступен только webkit2gtk-4.1
./build/bin/hrk-console-gui
```

Управление вынесено в кнопки — режимов, как в меню hkc, здесь нет, окно всегда одно и то же:

| Элемент | Где | Действие |
| --- | --- | --- |
| `Start` / `Restart` / `Stop` | панель, блок «Процесс» | запуск, перезапуск, остановка бота |
| `auto-restart` | панель, блок «Процесс» | вотчдог: сам поднимает бота, если тот упал сам по себе — тот же смысл, что клавиша `a` в TUI |
| `debug` | шапка | показать/скрыть строки уровня `[DEBUG]` |
| `порог: …` | шапка | по кругу: всё → warning и выше → error и выше |
| `Очистить` | шапка | сбросить экран лога и счётчики `⚠`/`✗` (файл на диске не трогает — только что вошло, снова появится) |
| поле поиска | над логом | подстрока без учёта регистра; префикс `re:` включает регулярное выражение (`re:spotify\|tl_cache`) |

Настройки (`debug`, панель, порог, auto-restart) сохраняются в тот же `~/.config/hkc/state.json`, что и у TUI, — значения общие для обоих интерфейсов.

### Как читается строка

```
00:13:04  WRN   spotify         Token refresh took 4.2s, retrying once   ×3
└─ время ─┘ │   └─ модуль ──┘   └─ сообщение ─┘                          └ повторов
            └ бейдж уровня
```

Насыщенный цвет несёт только бейдж уровня — `DBG`, `INF`, `WRN`, `ERR`, `CRT`; заливка есть у warning и выше, debug остаётся тихим. Время и модуль приглушены, сообщение остаётся читаемым. Дата не показывается: при живом просмотре она во всех строках одна.

Перенос, который был в самом логе (трейсбек, многострочный дамп), помечается `↳`.

### Что видно при скрытом DEBUG

Всё, кроме `[DEBUG]`, плюс сообщения самого бота (модуль `root`: баннер версии, старт сессии). Периодические служебные записи вроде `Reloaded N commands` намеренно остаются в скрытой части — бот пересобирает модули каждые 30 секунд.

## Состав

| Путь | Назначение |
| --- | --- |
| `cmd/hkc` | Точка входа: разбор режима, запуск меню и вьюера |
| `internal/tui` | Экраны на Bubble Tea: меню, вьюер лога, панель статистики, отрисовка строк |
| `internal/theme` | Палитра и стили — перекрашивать TUI нужно здесь |
| `internal/termwin` | Открытие нового окна терминала для режима «два окна» |
| `logfeed` | Разбор строк `heroku.log`, правила видимости, слежение за файлом с переживанием ротации |
| `botproc` | Процесс бота: поиск в `/proc`, запуск, остановка, аптайм, версия |
| `setup` | Автонастройка окружения бота, доустановка зависимостей загруженных модулей |
| `state` | Настройки экрана, сохранённые между запусками |
| `launch.sh` | Ярлык рабочего стола: открывает консоль в новом окне |

Пакеты `botproc`, `logfeed`, `setup` и `state` намеренно лежат вне `internal/` —
это чистый Go без завязки на терминал, и его переиспользует [`gui`](gui/)
(тот же бот, но нативное GUI-окно на Wails вместо TUI, отдельный Go-модуль в
этом же репозитории). Go не пускает `internal/*` за пределы дерева модуля,
поэтому TUI-специфика (`tui`, `theme`, `termwin`) остаётся под `internal/`, а
общая логика — нет.
