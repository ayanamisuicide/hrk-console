# heroku-console

Консоль для Telegram-юзербота [Heroku](https://github.com/coddrago/Heroku): запуск, остановка и живой просмотр логов из терминала.

```
╭─ HEROKU USERBOT ─────────────────────────────── ● live · 2.2.2 · 1ч 12м ─╮

── живой поток ────────────────────────────────────────────────────────────
00:13:01  ●  terminal        Command .sh executed by 8278874432
00:13:04  ▲  spotify         Token refresh took 4.2s, retrying once
00:13:07  ✗  tl_cache        Failed to resolve @unknown_channel
                           ↳ PeerIdInvalidError: could not find the input
                             entity for PeerUser(user_id=99)

───────────────────────────────────────────────────────────────────────────
 ● pid 4821  ·  ⏱ 1ч 12м  ·  ⚠ 3  ✗ 1          d — debug: скрыт  ·  q — выход
```

## Зачем

Смотреть `tail -f heroku.log` глазами тяжело: в живом логе 96% строк — это `[DEBUG]` от `urllib3`, `git` и внутреннего кэша, а нужные события тонут между ними. Здесь лог разложен по колонкам, шум скрыт по умолчанию, а состояние процесса видно в закреплённом подвале.

Лежит **вне** каталога бота намеренно: `heroku/log.py` умеет делать `reset_to_master()` и `restore_worktree()`, что может снести посторонние файлы внутри `~/Heroku`.

## Установка

Зависимостей нет — нужен `bash` 4+, `awk` и стандартные утилиты. Бот по умолчанию ищется в `~/Heroku`, каталог переопределяется переменной `HEROKU_DIR`.

```sh
git clone <этот-репозиторий> ~/heroku-console
chmod +x ~/heroku-console/*.sh
~/heroku-console/launch.sh
```

## Использование

`launch.sh` открывает окно терминала с меню (ghostty, kitty или alacritty — что найдётся). Режим можно передать аргументом и пропустить меню: `launch.sh 2`.

| Режим | Что делает |
| --- | --- |
| 1 · Подключиться к боту | Показывает логи, не трогая процесс |
| 2 · Перезапустить бота | Останавливает и запускает заново |
| 3 · Два окна | Родная консоль бота в отдельном окне + чистый лог в этом |
| 4 · Остановить бота | Просто `stop`, без просмотра логов |

В меню: `↑↓` или `jk` — выбор, `Enter` — запуск, `1`–`4` — сразу нужный режим, `q` — выход.

### Просмотр логов

| Клавиша | Действие |
| --- | --- |
| `d` | Показать или скрыть строки уровня `[DEBUG]` |
| `q` | Выйти из просмотра (бот продолжит работать) |

Выход из просмотра **не** останавливает бота — он живёт в своей сессии.

### Как читается строка

```
00:13:04  ▲  spotify         Token refresh took 4.2s, retrying once
└─ время ─┘  └─ модуль ──┘   └─ сообщение ─┘
          └ маркер уровня
```

Насыщенный цвет несёт только маркер уровня — `·` debug, `●` info, `▲` warning, `✗` error, `✖` critical. Время и модуль приглушены, сообщение остаётся светлым и читаемым. Дата не показывается: при живом просмотре она во всех строках одна.

Длинные сообщения переносятся с отступом под колонку сообщения. Перенос, который был в самом логе (трейсбек, многострочный дамп), помечается `↳`.

### Что видно при скрытом DEBUG

Всё, кроме `[DEBUG]`, плюс сообщения самого бота (модуль `root`: баннер версии, старт сессии). Периодические служебные записи вроде `Reloaded N commands` намеренно остаются в скрытой части — бот пересобирает модули каждые 30 секунд.

## Прямой запуск просмотра

```sh
./logs.sh [ключи]
```

| Ключ | Значение |
| --- | --- |
| `--history N` | Сначала показать N последних видимых записей |
| `--debug` | Сразу показывать `[DEBUG]` |
| `--from N` | Начать с N-й строки файла |
| `--skip-boot` | Не считать первую загрузку перезапуском |
| `--bare` | Без шапки |

Файл лога переопределяется переменной `LOG_FILE` — удобно, чтобы посмотреть чужой лог или проверить отрисовку, не трогая живой.

## Состав

| Файл | Назначение |
| --- | --- |
| `launch.sh` | Точка входа: открывает окно терминала с меню |
| `menu.sh` | Меню выбора режима и сами режимы |
| `logs.sh` | Живой просмотр лога: подвал, клавиши, слежение за процессом |
| `render.sh` | Разбор строки лога в колонки и её отрисовка |
| `ui.sh` | Тема, работа с процессом бота, общие примитивы вывода |
| `bot-console.sh` | Родная консоль: бот работает прямо в окне со своим tty |

Цвета собраны в секции «тема» в `ui.sh` — перекрашивать проект нужно там.
