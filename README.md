[![CI](https://github.com/ayanamisuicide/hrk-console/actions/workflows/ci.yml/badge.svg)](https://github.com/ayanamisuicide/hrk-console/actions/workflows/ci.yml)

Веб-панель управления Telegram-юзерботом [Heroku](https://github.com/ZetGoHack/Heroku).
Сервер работает рядом с ботом на Linux или WSL; панель открывается в браузере с любой ОС.

[Последний релиз](https://github.com/ayanamisuicide/hrk-console/releases/latest) · [Что изменилось в v2.5.1](CHANGELOG.md#251--2026-10-10) · [Инструкция по установке](docs/web.md)

## Возможности

| Раздел            | Что доступно                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Журнал            | Живой SSE-поток, поиск, фильтры, закладки и экспорт. Происшествия группируют ошибки и предупреждения.                           |
| Система           | Сводка состояния, живой график с лентой событий, ресурсы процесса бота, сеть и задержка до Telegram, что занимает диск и прогноз. |
| Модули            | Загрузка, готовность, приостановка и ошибки модулей. Кольцевая сводка, карта состояний, поиск, фильтры и обновление раз в секунду.                 |
| Администрирование | Управление ботом, автовосстановление, уведомления, пользователи и инвайты, настройки, история, резервные копии и обновления.     |
| Уведомления       | Telegram и webhook: остановка бота, перезапуски, ошибки модулей, длительная нагрузка на CPU, память и диск.                     |

Современный интерфейс-дашборд со светлой и тёмной темами, боковой панелью и нижними вкладками на телефоне, плавные анимации с поддержкой уменьшенного движения,
палитра быстрых действий (`Ctrl+K`) и установка панели как PWA.

### Админка

Пять рабочих областей: восстановление, доступ, настройки, история и обновления.
Управление ботом остаётся сверху, а переключение разделов не сбрасывает введённые настройки.

История разделена на действия, копии доступа и снимки конфигурации.
События сгруппированы и показываются постранично; подробности находятся справа,
а на телефоне открываются в отдельной карточке. Значения секретных параметров не загружаются в браузер.

### Автоматическое восстановление

По умолчанию панель перезапускает бота после трёх минут остановки или отсутствия ответа
основного цикла Python. Ожидание настраивается в админке от 30 до 3600 секунд;
наблюдение продолжает работать при закрытом браузере.

> [!IMPORTANT]
> Ручная остановка при включённом восстановлении тоже приводит к автоматическому запуску.
> Чтобы оставить бота выключенным, сначала отключите автовосстановление.

Если бот падает сразу после каждого перезапуска, наблюдение не крутит петлю бесконечно:
после заданного числа попыток подряд (по умолчанию 5) без 5 минут стабильной работы оно
приостанавливается до кнопки «Возобновить» в админке.

Мониторинг требует работающей панели. Для восстановления самой панели после завершения
процесса используется служба systemd. Готовность модуля означает успешную инициализацию,
а не гарантию выполнения каждой Telegram-команды или доступности сети.

### Уведомления

Панель пишет в Telegram, когда бот остановился или запустился, автовосстановление
перезапустило бота, не смогло этого сделать или приостановилось, модуль не загрузился,
а CPU, память или диск долго держатся выше порога. Создайте бота у [@BotFather](https://t.me/BotFather),
напишите ему любое сообщение и добавьте в `/etc/hkc/hkc.env`:

```sh
HKC_TELEGRAM_BOT_TOKEN="123456:ABC…"
HKC_TELEGRAM_CHAT_ID="ваш числовой ID или ID группы"
```

После `sudo systemctl restart hkc-web` события и пороги настраиваются в админке,
там же есть кнопка пробного сообщения. Те же события уходят на `HKC_WEBHOOK_URL`.
[Подробнее](docs/web.md#уведомления).

## Быстрый старт

### Установщик

На Linux или WSL с systemd и уже установленным Heroku:

```sh
curl -fsSL https://github.com/ayanamisuicide/hrk-console/releases/latest/download/install.sh | sudo bash
```

Установщик скачивает релиз под вашу архитектуру (amd64 или arm64), сверяет SHA-256 и версию,
кладёт исходники в `/opt/hrk-console`, создаёт `/etc/hkc/hkc.env` с новым административным
токеном и включает службы `hkc-web` и `hkc-update`. Каталог бота по умолчанию — `~/Heroku`
пользователя, вызвавшего `sudo`; другой задаётся через `--heroku-dir`. Ключ `--dry-run`
только проверяет окружение и релиз. Повторный запуск сохраняет настройки и токен.

### Из исходников

Для сборки вручную нужны Linux/WSL, Go версии из [go.mod](go.mod), `make`
и уже установленный Heroku с виртуальным окружением `.venv` или `venv`.

```sh
git clone --branch v2.5.1 --depth 1 https://github.com/ayanamisuicide/hrk-console ~/heroku-console
cd ~/heroku-console
make build

export HEROKU_DIR=/путь/к/Heroku
export HKC_ADMIN_TOKEN="$(openssl rand -hex 32)"
./bin/hkc-web
```

Откройте <http://localhost:8080/admin/> и введите `HKC_ADMIN_TOKEN`.
Создайте одноразовый инвайт для пользовательского аккаунта.
Сохраните административный токен в защищённом окружении службы для постоянной установки.

> [!IMPORTANT]
> Перед первым фоновым запуском один раз войдите в Telegram вручную.
> Веб-панель не отвечает на интерактивные вопросы авторизации.

При запуске бота из панели Python-мост мониторинга подключается автоматически,
без изменения исходников Heroku. Если бот запускается отдельно, установите мост
от владельца его окружения и затем перезапустите бота:

```sh
HEROKU_DIR=/путь/к/Heroku ./bin/hkc-web --install-modules-bridge
```

Подробности: [мониторинг модулей](docs/development.md#мониторинг-модулей-heroku).

## Релизы и обновление

Готовые сборки для Linux amd64 и arm64 доступны в [GitHub Releases](https://github.com/ayanamisuicide/hrk-console/releases/latest):
архивы `hkc-web-vX.Y.Z-linux-amd64.tar.gz` и `hkc-web-vX.Y.Z-linux-arm64.tar.gz`, файлы контрольных сумм SHA-256 и `install.sh`.

Для существующей установки используйте раздел «Обновления» в админке,
если служба обновления уже настроена. [Установка службы, проверка и откат](docs/web.md#обновления-панели-и-сверка-исходников).

Публикация релиза не обновляет работающий сервер автоматически.
Версию установленной панели можно проверить через `/api/version`.

## Безопасность и границы

- По умолчанию панель слушает только `127.0.0.1:8080`; для внешнего доступа настройте [HTTPS](docs/web.md#https-доступ).
- Административный токен даёт доступ к управлению установкой — храните его как пароль.
- Пользовательские роли разделяют наблюдение и управление ботом.
- Диагностика, диагностический ZIP и терминал удалены. Выполнение произвольных shell-команд через панель не поддерживается.
- Redis и Database убраны из редактора; ранее сохранённые значения в конфигурации не удаляются.
- Режим обслуживания, одноразовое расписание, TUI и SSH-клиент отсутствуют.
