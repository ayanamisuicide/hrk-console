# Использование

```sh
hkc              # проверки, затем меню выбора режима
hkc 2            # сразу нужный режим, без меню
hkc console      # родная консоль бота в текущем терминале (интерактивно)
hkc update       # проверить обновления hkc и, если есть, поставить
hkc --no-check   # пропустить автонастройку и проверки (для вызова из скриптов)
hkc --no-setup   # пропустить только автонастройку, проверки оставить
hkc --version    # версия сборки
hkc --help       # краткая справка
```

Перед запуском консоль доустанавливает недостающее (клонирует бота, ставит `python3`, `ffmpeg`, `venv`, зависимости) и прогоняет проверки окружения. Повторные запуски ничего не трогают — каждый шаг сначала смотрит, не сделано ли уже.

## Режимы

| Режим | Что делает |
| --- | --- |
| 1 · Подключиться к боту | Показывает логи, не трогая процесс |
| 2 · Перезапустить бота | Останавливает и запускает заново |
| 3 · Два окна | Родная консоль бота в отдельном окне + лог в этом |
| 4 · Остановить бота | Просто `stop`, без просмотра логов |
| 5 · Проверить обновления | Версия hkc на GitHub; при обновлении возвращает в меню, а не выходит |

В меню: `↑↓`/`jk` — выбор, `Enter` — запуск, `1`–`5` — сразу нужный пункт, `q` — выход.

## Клавиши вьюера

| Клавиша | Действие |
| --- | --- |
| `d` | Показать/скрыть строки уровня `DEBUG` |
| `s` | Показать/скрыть панель статистики |
| `w` | Порог показа по кругу: всё → warning+ → error+ |
| `m` | Выбрать модуль из панели и отфильтровать по нему |
| `a` | Автоперезапуск бота при падении: вкл/выкл |
| `/` | Поиск: подстрока или `re:шаблон`, пустой ввод снимает фильтр |
| `n` `N` | К следующей / предыдущей проблеме (warning и выше) |
| `r` `R` | К следующему / предыдущему перезапуску бота |
| `?` | Справка по клавишам |
| `↑↓` `jk` · `PgUp/PgDn` · `g`/`G` · колесо | Прокрутка |
| `q` | Выйти из просмотра (бот продолжит работать) |

Выход из просмотра **не** останавливает бота — он живёт в своей сессии.

## Как читается строка

```
00:13:04  WRN   spotify         Token refresh took 4.2s, retrying once   ×3
└─ время ─┘ │   └─ модуль ──┘   └─ сообщение ─┘                          └ повторов
            └ бейдж уровня
```

Насыщенный цвет несёт только бейдж уровня. Подряд идущие одинаковые записи схлопываются в одну со счётчиком `×N`; время показывается от последнего повтора, а счётчики `⚠`/`✗` продолжают считать каждое событие. Перенос, который был в самом логе (трейсбек, дамп), помечается `↳`.

При скрытом `DEBUG` видно всё, кроме него, плюс сообщения самого бота — баннер версии и старт сессии. Периодические служебные записи вроде `Reloaded N commands` остаются скрытыми: бот пересобирает модули каждые 30 секунд, это heartbeat, а не событие.

## Поведение

Прокрутка «прилипает» к низу: пока вы внизу, новые строки видны сразу; поднялись выше почитать историю — позиция остаётся на месте.

Если лог перестал читаться (файл удалили, права поменялись) — шапка говорит «⚠ лог не читается» и сколько это длится, слежение само подхватывает файл, когда он возвращается. Ротацию (`heroku.log` крутится на 10 МБ) и обрезание файла переживает без потери строк.

Заголовок окна терминала показывает счётчики `⚠`/`✗`, а на новый warning или error подаётся звуковой сигнал — большинство эмуляторов подсвечивают вкладку или иконку в доке.

## GUI

Нативное окно вместо терминала: тот же `HEROKU_DIR`, тот же лог, та же логика показа.

Собирается отдельно от `hkc`, потому что тянет свой тулчейн — [Wails](https://wails.io), Node и системные библиотеки webview. Разово:

```sh
sudo apt install libgtk-3-dev libwebkit2gtk-4.1-dev build-essential pkg-config nodejs npm
go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

Дальше — установить как обычное приложение (ярлык в меню и на рабочем столе, `sudo` не нужен):

```sh
./gui/install.sh
```

Удалить — `./gui/install.sh --uninstall`. Если нужно просто собрать, без ярлыков:

```sh
make gui                          # соберёт gui/build/bin/hrk-console-gui
./gui/build/bin/hrk-console-gui
```

`make gui` зовёт `wails build -tags webkit2_41` по полному пути в `$GOPATH/bin` — сам `wails` после `go install` оказывается там, а этого каталога в `PATH` обычно нет. Тег `webkit2_41` обязателен: на Ubuntu/Mint 24.04 в репозиториях остался только `webkit2gtk-4.1`, а Wails по умолчанию ищет `-4.0`.

Режимов, как в меню hkc, здесь нет — управление кнопками:

| Элемент | Где | Действие |
| --- | --- | --- |
| `Start` / `Restart` / `Stop` | под логом | запуск, перезапуск, остановка бота |
| поле поиска | под логом | подстрока или `re:шаблон`, как в TUI |
| `debug` | шапка | показать/скрыть строки уровня `DEBUG` |
| `порог: …` | шапка | по кругу: всё → warning+ → error+ |
| `auto-restart` | шапка | вотчдог — то же, что клавиша `a` в TUI |
| `Очистить` | шапка | сбросить экран лога и счётчики (файл не трогает) |
| `?` | шапка | справка по горячим клавишам |
| список модулей | статус-строка | клик раскрывает полный список; клик по модулю — фильтр по нему, повторный снимает |
| индикатор связи | статус-строка, справа | есть только в удалённом режиме и на Windows; клик открывает настройку подключения |

Статус-строка под шапкой видна всегда: жив ли бот и сколько он работает,
счётчики `⚠`/`✗` нарастающим итогом, три самых шумных модуля, действующий
порог и фильтр. Всё остальное — за кликом, чтобы лог занимал окно целиком.

### Проверки окружения

При старте (на Linux, с локальным ботом) окно сначала гоняет те же восемь
проверок, что и `hkc` — каталог бота, `venv`, `python3`, `ffmpeg` и так
далее. Если что-то не в порядке, рядом с «продолжить всё равно» появляется
кнопка **«Установить недостающее»**: она не чинит окружение прямо в окне
(часть шагов может попросить пароль `sudo`, а спросить его в webview
негде), а открывает настоящий терминал с той же автонастройкой, что уже
год есть у `hkc` (`setup.EnsureAll`). Когда терминал закончит — GUI-окно
нужно перезапустить самостоятельно, само оно не перечитывает окружение
на лету.

На Windows (и macOS) локального бота нет и быть не может — там ничего
не проверяется и не чинится, экран сразу показывает одну строку с
подсказкой подключиться к боту на Linux по SSH (клик по индикатору
связи, см. [«Бот на другой машине»](#бот-на-другой-машине) ниже).

### Обновления

Сразу после проверок окружения окно опрашивает оба канала — `stable` и `dev` —
и, если хоть в одном лежит сборка, отличная от запущенной, показывает их рядом
с датой публикации:

```
ОБНОВЛЕНИЯ                       сейчас запущено: v1.14.0
  stable   v1.15.0         2 ч назад       [Обновить]
  dev      v1.14.1-dev.3   19 мин назад    [Перейти]
```

Вердикта «что новее» здесь нет намеренно: тег dev-канала — своя версионная
линейка (следующий патч после последнего стабильного релиза + счётчик
коммитов dev-ветки после него, без хеша коммита), и у двух таких тегов от
разных релизов общего порядка нет — сравнивать каналы между собой можно
только по дате публикации, что и показано. «Перейти» на чужой канал меняет канал
насовсем, «Обновить» остаётся в своём. Экран запуск не задерживает: окно с
логом под ним уже работает, а если сети нет — он просто не появляется.

Само обновление показывает свои шаги — запрос к GitHub, поиск архива в релизе,
скачивание с полосой и объёмом, подмена на диске. Скачивание и распаковка идут
одной строкой, потому что происходят одновременно (tar читает из gzip, gzip из
сети). Полоса появляется только если сервер сообщил размер файла; иначе видно
просто сколько уже скачано. Подмена собственного файла и перезапуск — по-прежнему
два отдельных явных шага, автоматически ничего не перезапускается.

Горячие клавиши те же, что в TUI: `d`, `s`, `w`, `a`, `/`, `n`/`N` (к следующей
и предыдущей проблеме), `r`/`R` (по перезапускам), `g`/`G`, `?`. Пока курсор в
поле поиска, они не перехватываются — там печатают текст.

Запуск, перезапуск и остановка отмечаются строкой в самом логе: иначе падение
с автоподъёмом и ручной рестарт выглядят в истории одинаково. По этим отметкам
и прыгают `r`/`R`.

Настройки (`debug`, порог, auto-restart) сохраняются в общий с TUI `~/.config/hkc/state.json`.

### Бот на другой машине

GUI необязательно запускать на той же машине, где стоит бот — например, окно на Windows, а бот в `~/Heroku` на Linux в той же сети. Для этого готовые сборки: `hrk-console-gui-<версия>-windows-amd64.tar.gz` в [релизах](https://github.com/ayanamisuicide/hrk-console/releases/latest) — распаковать и запустить, ничего дополнительно устанавливать не нужно.

На машине с ботом нужен только уже настроенный доступ по SSH (по ключу — с паролем GUI не подключится):

```sh
sudo apt install openssh-server
sudo systemctl enable --now ssh
```

В GUI: клик по индикатору связи справа в статус-строке → хост/IP, пользователь, путь к приватному ключу, каталог бота на той машине (обычно просто `Heroku`). «Проверить соединение» — подключается и сразу отключается, ничего не сохраняя; «Подключиться» — сохраняет настройки и перезапускает окно уже в удалённом режиме. «Вернуться к локальному боту» в том же окне — обратно.

В удалённом режиме экран проверок окружения при старте не показывается (там проверяется локальная файловая система, а не выполняется вовсе, раз бот в принципе не здесь) — само содержимое `~/Heroku` на удалённой машине, конечно же, должно быть уже настроено обычным способом ([docs/setup.md](setup.md)).
