# Устройство проекта и разработка

Панель собирается из `cmd/hkc-web`. Файл `main.go` создаёт сервер, хранилища и
фоновые задачи. `routes.go` связывает адреса API с обработчиками. Авторизация,
администрирование, управление процессом, выдача журнала и HTTP-защита находятся
в отдельных файлах того же пакета Go; адреса API и поведение сохранены.

## Код браузера

`static/app.js` и `static/admin/admin.js` — точки входа нативных ES-модулей.
Они создают состояние страницы, подключают события и запускают обновление данных.
Фабрики из каталогов `modules/` получают объект страницы `ctx` явно и возвращают
именованные функции. Основное изменяемое состояние остаётся в этом объекте:
модули не зависят от порядка тегов подключения. Общие помощники анимаций
и отображаемая версия панели доступны через явно используемые свойства `window`.
При создании фабрики обработчики ещё не запускаются: ссылки на элементы и
начальное состояние задаёт точка входа перед подписками и запросами.

Пользовательская панель разделена на журнал и фильтры, ресурсы хоста,
происшествия, навигацию, авторизацию и управление ботом. Админка разделена
на пользователей и инвайты, аудит, настройки и резервные копии, автовосстановление,
диагностику, навигацию, авторизацию и обновления. Подписки на события находятся
рядом со своей функцией. Графики импортируются из `history-chart.js`.
Общие анимации остаются в `motion.js`, подключаемом перед точками входа.

Админка показывает одну рабочую область за раз: восстановление, доступ,
настройки, историю, диагностику или обновления. Выбор сохраняется в
`hkc-admin-view`; прежний `hkc-admin-tree` читается только для переноса выбора.
История разделена на доступные с клавиатуры вкладки действий, копий доступа
и снимков настроек. Списки имеют ограниченную высоту, детали аудита раскрываются
в строке. Переключение скрывает области, но не удаляет формы и несохранённый ввод.

Флаги `*Busy` предотвращают перекрытие одинаковых запросов. Сигнатуры
`*Signature` позволяют не пересобирать неизменившиеся списки. Административный
токен хранится в `sessionStorage`, предпочтения интерфейса — в `localStorage`.

## Стили и работа без сети

`style.css` и `admin/admin.css` импортируют тематические файлы из своих каталогов
`styles/`. Порядок важен: он сохраняет каскад, адаптивные правила и последующие
переопределения интерактивных состояний. Не меняйте порядок при переносе правил.
CSS оформлен для чтения, а не сжат вручную.

Новый модуль или стиль пользовательской панели добавьте в `ASSETS` внутри
`sw.js` и увеличьте версию кеша. Проверка PWA убеждается, что перезагрузка
без сети загружает весь набор зависимостей. Админка этим обработчиком
не кешируется; API тоже не сохраняется. Без сети доступна оболочка,
а не новые данные сервера.

## Мониторинг модулей Heroku

Раздел «Модули» опрашивает защищённый `/api/modules` раз в секунду, только
когда открыт и вкладка видима. Строки сохраняют DOM и раскрытие; анимируются
появление и смена состояния, а не каждый опрос. Настройка уменьшенного движения
отключает декоративные анимации.

`botproc/bridge/hkc_modules_bridge.py` наблюдает за загрузчиком внутри Python
Heroku и атомарно записывает `.hkc-modules.json` каждую секунду. Мост подключается
через `.pth` в виртуальном окружении при запуске бота из панели; исходники Heroku
не изменяются. Для бота, запускаемого отдельной службой, выполните от имени
владельца окружения `HEROKU_DIR=/путь/к/Heroku ./bin/hkc-web --install-modules-bridge`.
Данные появятся при следующем запуске бота. Перезапуск сам по себе эта команда
не выполняет. Для удаления подключения удалите только `hkc_modules_bridge.pth`
и `hkc_modules_bridge.py` из `venv/lib/python*/site-packages` этой установки.

Снимок другого PID не выдаётся как актуальный; через пять секунд без обновления
данные помечаются устаревшими. «Готов» означает завершение инициализации, не
проверку всех команд модуля. Ошибки импорта/инициализации и результат неудачной
загрузки отслеживаются отдельно. Если загрузчик поглотил исключение, подробность
нужно искать в журнале. Список охватывает обнаруженные файлы и заданные загрузчику
внешние модули; не загружавшиеся в этом запуске модули не считаются готовыми.

Проверка моста: `python3 botproc/bridge/test_bridge.py`.

## Автоматическое восстановление

В админке вместо одноразового расписания находится автовосстановление Heroku.
По умолчанию оно включено и ждёт 180 секунд; порог можно изменить от 30 до
3600 секунд. Закрывшийся процесс и отсутствие сигнала основного цикла Python
запускают отсчёт. Пустой журнал не считается зависанием. Сигнал `loopAt` создаёт
таймер asyncio, тогда как файл снимка обновляет отдельный поток: при блокировке
основного цикла поток не маскирует зависание свежим временем записи файла.

После истечения порога сервер останавливает процесс (SIGTERM, затем SIGKILL,
если он не завершился за пять секунд) и запускает его снова. Действия пользователя
и восстановление сериализованы. Новый PID получает полный срок на запуск;
неудачные попытки повторяются не чаще выбранного интервала. Результаты пишутся
в аудит. При включённом наблюдении ручная остановка тоже приводит к повторному
запуску через выбранный срок. Для длительной остановки выключите наблюдение.

Настройки сохраняются в `operations.json`; отсчёт начинается заново при запуске
панели. Старые поля удалённых функций игнорируются, задания из них не исполняются.
Наблюдение живёт в сервере панели, а не в браузере. Сама панель под systemd уже
имеет `Restart=always`. Наблюдение оценивает основной цикл Python, но не доказывает
исправность каждой команды или доступность сети Telegram.

## Язык документации

README, документацию, пояснения к изменениям и комментарии пишем по-русски.
Объясняем назначение функций, условия вызова, ограничения, владение состоянием
и неочевидные причины решений. Не дублируем очевидные строки кода.
Имена функций, ключи JSON, маршруты, команды, названия технологий и служебные
директивы (`//go:build`, `//go:embed` и подобные) сохраняем: это часть
программного интерфейса или формата инструмента, а не переводимый текст.

Методы с окончанием `Locked` вызываются при уже захваченной блокировке своего
хранилища. Не добавляйте внутри них повторный захват того же мьютекса.
Модели записи на диск и ответа HTTP различаются: например, хеш токена
сохраняется, но не выдаётся в списке токенов.

## Проверки

Запускайте `make test`, `make vet`, `make build`, `python3 deploy/test_update.py`
и `npm run test:ui`. Проверку гонок `go test -count=1 -race ./...` выполняйте
в Linux/WSL. Браузерные тесты проверяют темы на компьютере и телефоне,
снимки интерфейса, ошибки выполнения и загрузку без сети.

Коммит, публикация релиза и обновление запущенной службы — отдельные действия.
Версия в Git не доказывает, что именно она установлена: работающая панель
сообщает свою сборку через `/api/version`.
