# Веб-интерфейс

`hkc-web` — единственный интерфейс hrk-console 2.0. Сервер запускается рядом
с ботом на Linux/WSL, а панель открывается обычным браузером с любой ОС.
Кнопки управляют настоящим процессом Heroku, а лог приходит в браузер живым
SSE-потоком.

Для запуска Heroku используется Python из `venv/bin/python3` или
`.venv/bin/python3` внутри `HEROKU_DIR`.

## Сборка и запуск

```sh
make build
HKC_ADMIN_TOKEN='замените-на-длинный-случайный-секрет' \
HEROKU_DIR=/mnt/c/Users/ayanami/Heroku \
./bin/hkc-web
```

По умолчанию сервер слушает только `127.0.0.1:8080`. Из Windows при обычной
настройке WSL страница доступна по адресу <http://localhost:8080>.

Дополнительные переменные:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HKC_WEB_ADDR` | `127.0.0.1:8080` | адрес веб-сервера |
| `HKC_ADMIN_TOKEN` | случайный при каждом старте | секрет API создания инвайтов |
| `HKC_AUTH_FILE` | `~/.config/hkc/web-auth.json` | база пользователей и инвайтов |
| `HEROKU_DIR` | `~/Heroku` | каталог бота |
| `HKC_WEBHOOK_URL` | не задан | HTTPS endpoint для JSON-уведомлений |
| `HKC_TELEGRAM_BOT_TOKEN` | не задан | токен бота от @BotFather для уведомлений |
| `HKC_TELEGRAM_BOT_TOKEN_FILE` | не задан | файл с токеном вместо переменной |
| `HKC_TELEGRAM_CHAT_ID` | не задан | числовой ID чата или `@username` канала |
| `HKC_TELEGRAM_API_URL` | `https://api.telegram.org` | адрес Bot API, например локального сервера |
| `HKC_TELEGRAM_ADMIN_IDS` | не задан | ID пользователей Telegram через запятую, которым бот подчиняется |
| `HKC_TELEGRAM_WEBAPP_URL` | не задан | HTTPS-адрес панели для мини-приложения, например `https://машина.tailnet.ts.net` |
| `HKC_PUBLIC_STATUS` | не задан | значение `1` открывает `/api/public/status` и страницу `/status.html` без входа |
| `HKC_LOG_ARCHIVE_MB` | `300` | предел сжатого архива журнала в МБ; `0` выключает архив |
| `HKC_LOG_ARCHIVE_DAYS` | `30` | сколько дней хранить сжатые копии журнала |

Если `HKC_ADMIN_TOKEN` не задан, сервер печатает временный токен при старте.
Для постоянной установки его следует задать явно и хранить как пароль.

## Инвайты и регистрация

Инвайт создаёт только администратор. Пример для инвайта на 24 часа:

```sh
curl -X POST http://localhost:8080/api/admin/invites \
  -H 'Authorization: Bearer замените-на-ваш-HKC_ADMIN_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"expiresHours":24}'
```

Ответ содержит одноразовый `invite` и готовый `registrationUrl`. Получатель
открывает эту ссылку и придумывает собственные логин и пароль. Код можно
также вставить вручную через кнопку «У меня есть инвайт». После
регистрации инвайт удаляется. Пароль хранится только в виде bcrypt-хэша.

Сессия находится в `HttpOnly`/`SameSite=Strict` cookie и живёт 30 дней либо
до перезапуска сервера. Перезапуск не удаляет пользователя — потребуется
только войти заново.

Инвайт выдаётся оператору или наблюдателю. Оператор может запускать и
останавливать бота; наблюдатель видит состояние системы и журнал.
Владелец административного токена меняет роли в админке. Ранее созданные
пользователи автоматически считаются операторами.

В основной панели доступны журнал с фильтрами и экспортом, единый экран
ресурсов WSL/Linux (CPU, общая RAM, диск, load average и uptime), смена цветового акцента и быстрые действия `Ctrl+K`. Счётчики ошибок относятся к последним 1000
строкам лога, а не ко всей истории.

Для публичной страницы статуса установите `HKC_PUBLIC_STATUS=1`; по умолчанию
она не раскрывает состояние сервиса.

## Вкладка «Система»

Сводка сверху объясняет состояние одной фразой. Ниже — карточки ресурсов со спарклайнами,
живой график и подробности. График переключается между видами «Ресурсы», «Бот» и «Сеть»;
выделение мышью приближает участок, двойной щелчок или кнопка возвращают масштаб,
щелчок по легенде скрывает серию. Под графиком — лента событий: остановки и перезапуски
бота, действия автовосстановления, ошибки модулей и превышения порогов.

Данные приходят из `GET /api/system/history?range=live|1h|24h` (сжатые точки, перезапуски,
события, пороги и статистика) и `GET /api/system/details` (сводка, процесс бота, сеть,
диск, WSL, процессы). Список процессов хоста видят только операторы. Проверка связи
с Telegram — TCP-соединение с адресами дата-центров без передачи данных; её отключает
`HKC_NETWORK_PROBE=0`. Размер каталогов пересчитывается раз в пять минут, обход ограничен
по времени и числу файлов.

## Уведомления

Каналы задаются окружением службы и в браузер не передаются. Telegram включается парой
`HKC_TELEGRAM_BOT_TOKEN` и `HKC_TELEGRAM_CHAT_ID`. Чтобы узнать ID личного чата, напишите
боту и откройте `https://api.telegram.org/bot<токен>/getUpdates`; для группы добавьте бота
в неё, ID группы начинается с `-100`. Webhook включается `HKC_WEBHOOK_URL` (только HTTPS
без логина в адресе). Некорректное значение отключает только свой канал и пишется в журнал службы.

События:

| `event` | Когда |
| --- | --- |
| `bot.started`, `bot.stopped` | процесс бота появился или пропал (проверка раз в 15 секунд и после действий) |
| `watchdog.recovered`, `watchdog.failed` | автовосстановление перезапустило бота или не смогло |
| `watchdog.suspended` | исчерпан лимит перезапусков подряд |
| `module.error` | модули перешли в ошибку в текущем запуске; несколько модулей объединяются в одно сообщение |
| `host.cpu`, `host.memory`, `host.disk` | значение держится выше порога заданное время (`severity: critical`) и вернулось на 5% ниже порога (`severity: ok`) |
| `test` | кнопка «Отправить проверку» в админке |

В админке («Восстановление» → «Уведомления») выбираются группы событий, пороги
(0 выключает ресурс, иначе 50–100%) и длительность превышения (30–3600 секунд,
по умолчанию 300). Настройки хранятся в `operations.json` рядом с базой авторизации.
Общий лимит — 20 сообщений за 10 минут; лишние события пропускаются с записью в журнал.
Первый снимок модулей после запуска панели только запоминается, чтобы перезапуск
панели не повторял уже известные ошибки.

Webhook получает JSON `{"service":"Heroku bot","event":"…","severity":"…","title":"…",
"message":"…","host":"…","time":"…"}`. Для `bot.started` и `bot.stopped` добавляется
прежнее поле `status` (`running` или `stopped`), поэтому старые обработчики продолжают работать.

## Управление из Telegram

Раздел «Telegram» в админке показывает состояние бота, пошаговую настройку, команды и
действия, выполненные из Telegram. Есть два уровня, и первый не зависит от второго:

1. **Команды бота и обычные фразы** — `/status`, `/logs`, `/errors`, `/find`, `/mute`, `/unmute`,
   `/run`, `/restart`, `/stop`, `/update`, `/help`, а также то же самое словами без слэша
   (см. «Разговор с ботом» ниже). Панель сама опрашивает
   Bot API (`getUpdates`), открытый порт не нужен. Нужны `HKC_TELEGRAM_BOT_TOKEN`,
   `HKC_TELEGRAM_ADMIN_IDS` и переключатель «Управление из Telegram» в админке (по умолчанию
   выключен). `HKC_TELEGRAM_CHAT_ID` для команд не обязателен — он только для уведомлений.
2. **Мини-приложение** — та же панель в компактном виде внутри Telegram: состояние бота с
   кнопками, живые графики сервера, модули с ошибками и журнал. Открывается кнопкой «Панель»
   в чате с ботом или командой `/app`. Нужен ещё `HKC_TELEGRAM_WEBAPP_URL`.

**Разговор с ботом.** Слэш не обязателен: бот понимает обычные фразы (разбор по основам слов,
без нейросети, поэтому ответ на одну и ту же фразу всегда одинаков):

| Фраза | Что делает |
| --- | --- |
| «меню», `/menu`, `/start` | Главное меню — одно сообщение-дашборд, которое бот сам обновляет (см. ниже). |
| «статус», «как дела», «что с ботом» | Сводка: бот, CPU/память/диск, ошибки за час и самые шумные модули, тишина. Под ней кнопки «Обновить» (правит это же сообщение), «Логи», «Ошибки», «Перезапустить»/«Остановить» или «Запустить». |
| «покажи логи», «логи 30», «логи updates», «логи за 10 минут» | Записи журнала с группировкой повторов. Кнопки «Старее», «Свежее», «Только ошибки», «Файлом» и фильтр по шумным модулям. |
| «ошибки», «что упало», «что случилось» | Ошибки за 6 часов, сгруппированные по причине (числа в тексте не различают причины): `×9 updates · …`. Кнопки `🧵 N` открывают traceback самой свежей записи группы. |
| «найди таймаут» | Поиск по всему журналу, включая ротации и traceback. Любая непонятная фраза тоже ищется в журнале. |
| «запусти», «перезапусти», «останови» | Действия над ботом. Перезапуск и остановка из слов **всегда** подтверждаются — кнопкой или ответом «да» (даже если подтверждение выключено для команд). «Не перезапускай», «отмена», «нет» ничего не выполняют. |
| «обнови» | Проверка новой версии панели (см. ниже). |
| «тишина на час», «помолчи до утра», «выключи уведомления на 30 минут» | Глушит уведомления в Telegram. Критичные (бот упал) приходят всё равно; «совсем» глушит и их. «Включи уведомления» возвращает. Состояние хранится в `telegram-mute.json`, перезапуск панели его не сбрасывает. |

В группе бот откликается на слова только при обращении по имени («@имя статус»); в личном
чате — на любое сообщение. Секреты в журнале (токены Telegram и `hkc.`, ключи `sk-…`, JWT,
пароли в адресах и после `token=`/`password:`) скрываются и в сообщениях, и в файле. Список
шаблонов неполный: перед пересылкой файла стоит его просмотреть.

**Главное меню.** Одно сообщение в личном чате с администратором: состояние бота, версии бота и панели (⬆️, если вышла новая), загрузка CPU/памяти/диска полосками, нагрузка бота, сеть, число работающих модулей и названия упавших, число ошибок и предупреждений за час (самих записей журнала в меню нет), последнее событие, автовосстановление и тишина. Бот правит это сообщение по таймеру: каждые 10 секунд, пока вы нажимаете кнопки, и раз в минуту, когда вы давно не нажимали. Период выбирается кнопкой «⏱» (1 с / 5 с / 10 с / 1 мин / выкл) или в «⚙️ Ещё». Секундный режим держит ровную частоту (срок считается от прошлого срока, а не от момента правки), а текст каждый раз меняется, иначе Telegram отверг бы правку как «не изменилось». Telegram не любит частых правок в один чат, поэтому на каждый ответ 429 бот ждёт столько, сколько просит Telegram (`retry after`), и обновляет реже на ступень (2 → 5 → 10 → 30 с), о чём сказано в подписи меню («частота снижена: лимит Telegram»). Новый выбор периода кнопкой возвращает выбранную частоту. Кнопки переключают экраны в том же сообщении («Модули», «Ещё»), а «Логи» и «Ошибки» открывают отдельные сообщения. «⚙️ Ещё» также закрепляет меню, проверяет обновление и включает тишину до утра. Повторное «меню» переносит сообщение вниз чата и сохраняет настройки. Меню хранится в `telegram-menu.json` и переживает перезапуск панели; если сообщение удалено или недоступно, бот забывает его, а не стучится впустую, а при лимите Telegram (429) выдерживает паузу. Меню обновляется, только пока бот слушает команды (иначе кнопки были бы мертвы). В группах меню не работает.

**Анимация ответов.** В личном чате ответы бота набираются на глазах, как у нейросети:
пока бот готовит ответ, Telegram показывает «Думаю…», затем текст появляется по словам
(метод Bot API `sendMessageDraft`), а в конце приходит обычное сообщение с кнопками.
В группах и при отказе Telegram от черновиков ответы приходят сразу; отказ логируется один
раз и анимация не пробуется до перезапуска панели.

**Уведомления как инциденты.** Падение бота и его запуск — одно сообщение: при падении оно
приходит с кнопками «Запустить» и «Логи», а при запуске правится на «Бот запущен · Простоял
2 мин 10 с» с кнопкой «Что случилось» (журнал за этот период). То же для нагрузки сервера.
Повторы одной ошибки модуля правят первое сообщение (`×3 · последний раз 18:42:07`), а не
плодят новые; правка не звенит. Открытые инциденты хранятся в `telegram-incidents.json` и
переживают перезапуск панели. Кнопки есть, только когда бот слушает команды.

**Обновление панели.** Когда выходит новая версия, уведомление в Telegram приходит с кнопкой
«Обновить до vX»: одно нажатие запускает ту же установку, что и страница «Обновления», в
сообщении появляется «Обновляю…», а после перезапуска панели — «Обновлено до vX» (или причина
неудачи, если служба откатила сборку). Тот же сценарий по команде `/update`: бот проверяет
GitHub и предлагает кнопку, если есть что ставить, либо объясняет, что мешает (например,
несохранённые изменения в исходниках). Кнопка есть, только когда бот слушает команды —
иначе нажатие было бы некому обработать. Ход установки запоминается в
`telegram-update.json` рядом с `HKC_AUTH_FILE`, чтобы новый процесс панели дописал итог в то
же сообщение. Установка пишется в журнал действий от имени `telegram:@username`.

Бот подчиняется только ID из `HKC_TELEGRAM_ADMIN_IDS` и молчит для остальных. Тех, кто писал
без доступа, раздел показывает с готовой строкой для `hkc.env` — так проще узнать свой ID:
включите управление, напишите боту `/start` и скопируйте строку. Остановка и перезапуск
по умолчанию подтверждаются кнопкой под сообщением; кнопка действует минуту и срабатывает
один раз. Команды старше двух минут не выполняются, поэтому всё, что накопилось, пока
панель была выключена, пропадает. Действия пишутся в журнал действий от имени
`telegram:@username`.

Используйте для панели **отдельного бота**. Если тем же ботом пользуется другая программа,
например инлайн-бот Heroku, Telegram не даст слушать его двоим. Панель это распознаёт,
перестаёт опрашивать и объясняет причину в админке, чтобы не мешать второй программе.

Мини-приложение загружает клиент Telegram на вашем устройстве, а не сервер Telegram.
Поэтому подходит адрес, доступный только в вашей сети Tailscale:

```sh
sudo tailscale serve --bg 8080
# в /etc/hkc/hkc.env:
HKC_TELEGRAM_WEBAPP_URL="https://машина.tailnet.ts.net"
HKC_TRUST_PROXY=1
```

Тогда приложение откроется на устройствах, где включён Tailscale, а для остальных панели
в интернете нет. Вход в мини-приложение не нужен: Telegram подписывает данные запуска
токеном бота, панель проверяет подпись (не старше суток) и выдаёт сессию на 12 часов
только администраторам из списка. Выключенный переключатель или убранный из списка ID
закрывают доступ сразу. Страницы `/tg/` разрешают встраивание только веб-клиенту Telegram
и загружают скрипт моста с `telegram.org`; остальная панель остаётся с прежними
заголовками.

## Административная панель

Откройте <http://localhost:8080/admin/> и введите `HKC_ADMIN_TOKEN`. Панель
показывает зарегистрированных пользователей, дату регистрации, количество
активных сессий, последнюю активность и состояние онлайн. Пользователь
считается онлайн, если обращался к серверу за последние 30 секунд.

Там же можно создавать и отзывать инвайты, копировать готовые ссылки
регистрации и удалять пользователей. При удалении пользователя все его
текущие сессии немедленно завершаются. Сессии переживают перезапуск панели, в том числе
обновление: они лежат в `sessions.json` рядом с `HKC_AUTH_FILE` (права 0600) не как токены, а
как их SHA-256, так что утёкший файл не даёт войти. Административный токен хранится
только в `sessionStorage` вкладки и удаляется кнопкой «Закрыть сессию».

Раздел «Резервные копии доступа» сохраняет базу пользователей и инвайтов в
`backups/` рядом с `HKC_AUTH_FILE`. Перед восстановлением создаётся ещё одна
копия текущей базы, а после восстановления завершаются все пользовательские
сессии. Копии содержат хэши паролей и действующие инвайты, поэтому каталог
нужно защищать как секрет.

Редактор `config.json` показывает только наличие параметров, без раскрытия их
значений. Перед сохранением доступна валидация и список изменяемых ключей.
Снимки конфигурации и их восстановление убраны в 2.20.1: панель больше не сохраняет
версии в `.hkc-config-history`; уже сохранённые там файлы не трогаются и могут быть удалены вручную.

Диагностика и административный терминал удалены вместе с API выполнения команд и скачивания диагностического архива.

Управление API-токенами убрано из админки. Уже выпущенные токены продолжают
работать, а служебный API сохранён для совместимости. В базе хранится SHA-256
хэш. Токен передаётся
в заголовке `Authorization: Bearer hkc.…`. Доступные маршруты:
`GET /api/v1/status`, `GET /api/v1/logs`, `POST /api/v1/bot/start|stop|restart`.
Токен `read` не может управлять ботом. Отозванный токен перестаёт работать сразу.

История действий показывает последние 100 событий; файл `audit.jsonl`
автоматически удерживает не более 1000 последних записей.

## Журнал

Страница журнала читает `heroku.log` и его ротации (`heroku.log.1`, `.2`, …) и
показывает записи целиком: строки traceback входят в запись, а не идут
отдельными строками. Все маршруты требуют входа в панель.

Лента собрана из нескольких источников, слитых по времени:

- `heroku.log` с ротациями и **архивом**. Бот держит одну ротацию по 10 МБ и при следующей
  перезаписывает её, поэтому панель раз в 30 секунд снимает сжатую копию свежей ротации в
  `log-archive/` рядом с `HKC_AUTH_FILE` (права 0600) и убирает копии сверх
  `HKC_LOG_ARCHIVE_MB` или старше `HKC_LOG_ARCHIVE_DAYS`. Поиск, шкала, частые ошибки и Telegram
  читают архив вместе с живыми файлами; копия ротации, которая ещё лежит рядом, не читается
  дважды. Рядом со счётчиком записей видно, с какой даты хранится история.
- **Журнал панели** `panel.log` рядом с `HKC_AUTH_FILE` (до 4 МБ и одна ротация). Модуль
  `process` — вывод процесса бота, которого нет в `heroku.log`: traceback падения, ошибки до запуска
  логирования, `print()` модулей, `Killed` от нехватки памяти. Панель читает `.startup.log` и
  отбрасывает копии записей бота: у каждой продублированной записи пропускается ровно столько
  строк продолжения, сколько их у неё в `heroku.log`. Вывод прошлого запуска сохраняется в
  `.startup.log.1`. Модуль `panel` — действия людей и автоматики (запуск, остановка, перезапуск,
  автовосстановление, обновление, настройки, правила и уровни журнала) и события панели (бот
  упал или запустился, пороги ресурсов, новая версия). Вход, пользователи и токены остаются только
  в журнале действий админки.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/logs/entries` | Записи от новых к старым, постранично. Параметры: `level` (через запятую, `ERROR` включает `CRITICAL`), `module`, `q` (текст в сообщении, модуле и traceback), `from`, `to` (мс Unix), `limit` (до 500), курсор `before` (время самой старой загруженной записи) и `skip` (сколько загруженных записей имеют это время). |
| `GET /api/logs/stats` | Число записей по интервалам для шкалы (`bucket` в мс, по умолчанию 5 минут, окно 6 часов) и список модулей. Границы интервалов привязаны к эпохе, а не к моменту запроса, чтобы шкала не дёргалась. |
| `GET /api/logs/context` | Запись (`ts`, `id`) и до `n` соседей с каждой стороны (до 50); `before` и `after` задают число более ранних и более поздних отдельно (до 200). |
| `GET /api/logs/rules` | Правила журнала: группа записей (`key` — подпись из «Частых ошибок»), `hide` и `notify` (`count` раз за `minutes`). |
| `POST /api/logs/rules` | Создать или изменить правило группы: `key` или запись (`ts`, `id`), `hide`, `notify`. Правило без действий удаляется. Только оператор. |
| `DELETE /api/logs/rules/{id}` | Удалить правило. Только оператор. |
| `GET /api/logs/levels` | Уровни журнала модулей, заданные из панели, признак `applied` (мост в процессе бота подтвердил уровень) и `available`. |
| `POST /api/logs/levels` | Задать уровень логгера (`logger`, `level`: `DEBUG`, `INFO`, `WARNING`, `ERROR` или пусто — по умолчанию, `minutes`: 0 — до отмены). Только оператор. |
| `GET /api/logs/archive` | Сводка архива: число копий, размер, самая ранняя запись, пределы. |
| `GET /api/logs/problems` | Частые ошибки за окно: одинаковые записи (модуль, сообщение без чисел, адресов и хэшей, тип исключения) в группах со счётчиком, временем первой (`first`) и последней записью (`last`) и подсказкой для поиска (`query`). Параметры: `from`, `to` (по умолчанию последние 6 часов), `level` (по умолчанию `ERROR`), `module`, `q`, `limit` (до 50). |
| `GET /api/logs/stream` | SSE: каждое событие — запись целиком. Запись уходит, когда за ней пришла следующая или прошло 0,4 с тишины. Событие `state` сообщает, читается ли файл. |

Старые `GET /api/logs?limit=` и `GET /api/events` (сырые строки) сохранены для
мини-приложения Telegram и служебного API. Мини-приложение собирает строки в записи сам:
traceback сворачивается под своей записью.

Чтение устроено так, что цена запроса не растёт с размером файла: журнал читается блоками
с конца, поэтому свежие 200 записей отдаются за доли миллисекунды, а поиск останавливается,
как только набрал нужное число. Память ограничена блоком (256 КиБ) и найденными записями,
а не размером файла.

Секреты в журнале (токены бота и GitHub, ключи, JWT, пароли в адресах, `Authorization`) скрывают
те же правила, что и ответы бота в Telegram. Сырой журнал видит только оператор панели;
наблюдатель, API-токен чтения и мини-приложение Telegram получают скрытый текст, причём поиск
(`q`) у них идёт по скрытому тексту: фрагмент секрета ничего не находит, подобрать его по
совпадениям нельзя.

Traceback Python разбирается на кадры (`modules/log-trace.js`): в сложенной записи видна причина
(`ServerTimeoutError: …`), в раскрытой — свои кадры с файлом, строкой и кодом, подряд идущие
кадры библиотек (`site-packages`, `lib/python3`) свёрнуты в одну строку, исключение выделено, а
«Копировать» берёт исходный текст. Разбор строится при раскрытии. Формат не Python показывается
как есть. Над лентой — четыре плитки сводки за окно или выбранный диапазон (ошибки, предупреждения, записи, самый шумный модуль); первые две и последняя — быстрые фильтры. У каждой записи слева плитка уровня (треугольник — ошибка, часы — предупреждение), справа время и модуль. Рядом с шкалой — стрелки «Ошибки ‹ ›»
(клавиши `[` и `]`) и кнопка «Сейчас». Стрелки идут по загруженной ленте, затем подгружают
старые записи, затем перескакивают на ближайший интервал шкалы с ошибками. У имени модуля
цветная точка (оттенок зависит от имени), у времени записи подсказка «сколько назад».

**Правила журнала.** В «Частых ошибках» у группы есть «Скрыть» и «Уведомлять…», в деталях записи —
«Скрыть такие». Скрытая группа пропадает из ленты, плиток, шкалы и ответов бота в Telegram; кнопка
«Скрытые» под поиском показывает её снова (`hidden=1` у маршрутов ленты и шкалы), а «Частые ошибки»
продолжают её считать с пометкой «скрыто». Уведомление уходит теми же каналами, что и остальные
(событие `log.rule`), когда группа повторилась N раз за M минут, и повторяется не раньше, чем через
M минут. Правила общие для всех и хранятся в `log-rules.json` рядом с `HKC_AUTH_FILE`; список всех
правил с удалением — в «Частых ошибках».

**Уровни журнала модулей.** В деталях записи — «Уровень журнала модуля»: подробно (DEBUG), обычно,
только предупреждения или только ошибки, на 15 минут, час, сутки или до отмены. Панель пишет
`.hkc-log-levels.json` в каталог бота, мост наблюдения внутри процесса раз в секунду ставит логгерам
эти уровни, снимает истёкшие и возвращает исходные. Бот не перезапускается. Мосту нужен запуск бота
из панели этой версии; до этого журнал подсказывает перезапустить бота. Действующие уровни видны
строкой под фильтрами.

Фильтры в строке запроса: `level:error`, `module:updates`, остальное — текст. Уровень выбирается
плитками (повторное нажатие снимает, «Записей» — все уровни), модуль — кнопками четырёх самых шумных
модулей или списком «Ещё модули». Закладки и сохранённые фильтры хранятся в браузере. Шкала
поддерживает выделение диапазона мышью; выделение, доходящее до «сейчас», остаётся живым.

Запрос и открытая запись хранятся в адресе страницы: `#logs?level=ERROR&module=net&q=таймаут`,
`&from=`/`&to=` для диапазона и `&entry=<ts>~<id>` для записи. Перезагрузка не сбрасывает фильтр,
кнопка «Ссылка» в заголовке копирует текущий запрос, а «Ссылка» в панели деталей — ссылку на саму
запись: она открывает журнал на месте записи (диапазон ±15 минут, если запись старше загруженной
ленты) с панелью деталей. В других разделах адрес журнала убирается.

Пока читаешь историю (лента прокручена вверх), шапка сворачивается в строку поиска с итогами окна,
переходами между ошибками и узкой шкалой; «Развернуть» или возврат к живому хвосту возвращают её.
На телефоне журнал занимает экран над нижней навигацией, лента прокручивается внутри него, а панель
деталей открывается шторкой с затемнением (клик по нему закрывает).

«Частые ошибки» открывают в панели список повторяющихся ошибок или предупреждений за окно шкалы
(`/api/logs/problems`). Клик по группе показывает в ленте ровно её записи (уровень, модуль и
устойчивая часть сообщения), «Последняя» открывает последнюю запись группы. В деталях записи
окружение листается кнопками «Раньше» и «Позже», а клик по соседней строке открывает ту запись.

## Установка одной командой

`deploy/install.sh` прикладывается к каждому релизу:

```sh
curl -fsSL https://github.com/ayanamisuicide/hrk-console/releases/latest/download/install.sh | sudo bash
```

Нужны Linux или WSL с работающим systemd, `git`, `curl`, `tar`, `python3` и каталог Heroku.
Установщик выбирает архив по `uname -m` (amd64 или arm64), сверяет имя и SHA-256,
допускает в архиве только обычный файл `hkc-web` с ELF-сигнатурой и проверяет встроенные
версию и коммит. Затем клонирует репозиторий в `/opt/hrk-console` с локальной `main`
ровно на коммите релиза, кладёт бинарник в `bin/`, создаёт `/etc/hkc/hkc.env` (права 0600)
с новым административным токеном, подставляет пути в шаблоны служб и ждёт ответа `/api/version`.
Если панель работает не от root, установщик добавляет юнит `hkc-update.path`: панель только
кладёт файл задания, а обновление запускает systemd. Правила `sudo` для этого больше нет —
с ним не работал `NoNewPrivileges=true` в службе панели (см. «Обновления»).

| Ключ | Переменная | По умолчанию |
| --- | --- | --- |
| `--heroku-dir` | `HEROKU_DIR` | `~/Heroku` пользователя, вызвавшего `sudo` |
| `--user` | `HKC_SERVICE_USER` | владелец каталога бота |
| `--dir` | `HKC_SOURCE_DIR` | `/opt/hrk-console` |
| `--addr` | `HKC_WEB_ADDR` | `127.0.0.1:8080` |
| `--version` | `HKC_VERSION` | последний стабильный релиз |
| `--dry-run` | — | проверить окружение и релиз без изменений |

Существующий `/etc/hkc/hkc.env` не перезаписывается. Существующая копия исходников
должна быть чистой веткой `main` и продвигается только fast-forward. Каталог состояния
обновлений — `/var/lib/hkc/updates`. Токен администратора: `sudo grep HKC_ADMIN_TOKEN /etc/hkc/hkc.env`.

## Обновления

Раздел «Обновления» в админке показывает текущую версию, вышедшие изменения из CHANGELOG
и кнопку «Обновить». Можно поставить любой другой релиз или вернуть резервную сборку.
Ход установки виден по шагам; во время перезапуска панели страница ждёт и подключается сама.
О новой версии приходит уведомление (событие `update.available`).

Там же кнопка «Перезапустить панель» (`POST /api/admin/panel/restart`, только администратор):
панель отвечает и завершает процесс, systemd поднимает её снова (`Restart=always`).
Бот — дочерний процесс панели, но служба настроена с `KillMode=process`: перезапуск и
остановка `hkc-web` завершают только панель, бот работает дальше, и новая панель находит его
по `/proc`. Старым установкам служба обновления добавляет то же правило в
`/etc/systemd/system/hkc-web.service.d/keep-bot.conf`. Без systemd и во время обновления
перезапуск недоступен.

Установку выполняет отдельная root-служба `hkc-update.service`, поэтому она переживает
перезапуск панели. Панель оставляет задание в `update-request.json` рядом с `HKC_AUTH_FILE`
(или по пути `HKC_UPDATE_REQUEST_FILE`). Служба стартует по одному из двух путей: если
панель работает не от root, файл задания замечает юнит `hkc-update.path`, и systemd запускает
службу сам — защитные ограничения службы панели (`NoNewPrivileges`, `RestrictSUIDSGID`) остаются
на месте; если панель от root, она вызывает `systemctl start hkc-update.service` сама. Установки,
сделанные до появления `hkc-update.path`, получают юнит при повторном запуске установщика (он
сохраняет данные); пока его нет, страница обновлений показывает блокер с подсказкой, а при
ручном запуске `sudo systemctl start hkc-update.service` служба дописывает юнит сама. Служба
читает файл без перехода по ссылкам и проверяет его по строгой схеме. Архив сверяется по SHA-256, составу и встроенной
версии; текущая сборка сохраняется в `HKC_UPDATE_DIR/backups` (последние 5), при неудачном
запуске возвращается автоматически. Ход работы — `HKC_UPDATE_DIR/status.json`, список копий —
`backups.json`; оба файла читаемы панелью и не содержат секретов.

Исходники в `HKC_SOURCE_DIR` продвигаются только fast-forward; несохранённые изменения в них
блокируют установку (страница объясняет, что сделать). Дополнительная копия
`HKC_LOCAL_SOURCE_DIR` установку не блокирует — при пропуске появляется предупреждение.
Перенос старой WSL-панели на службы: `python3 deploy/install_wsl.py --binary … --check-only`.

на том же узле. Чтобы принимать `X-Forwarded-Proto: https` только от локального
proxy, задайте `HKC_TRUST_PROXY=1`; без этого флага заголовок не считается
доверенным.
