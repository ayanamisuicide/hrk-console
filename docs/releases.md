# Выпуск подписанных обновлений

Поддерживаемые варианты: TUI и локальный бот на Linux; Windows GUI подключается к Linux-боту по SSH. Автонастройка бота поддерживает Debian/Ubuntu/Mint с apt-get. `hkc --no-setup` запускает проверки без установки зависимостей. Windows-сборка GUI: `powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1`.

Go берётся из корневого go.mod (оба Go-модуля должны требовать одну версию). Wails CLI должен совпадать с версией в gui/go.mod; Windows bootstrap определяет её автоматически, workflow закрепляет ту же версию. При обновлении Wails нужно менять обе настройки.

## Подпись

`internal/releaseauth/public.key` — открытый ключ Ed25519, встроенный в приложение. Закрытый ключ не хранится в Git и не выводится в лог. Actions ожидает repository secret `HKC_RELEASE_SIGNING_SEED`: base64 от 32-байтового seed Ed25519. Подписывающая команда проверяет, что секрет соответствует встроенному открытому ключу.

Оба release workflow подписывают каждый `.tar.gz` командой `go run ./cmd/release-sign ./*.tar.gz` и публикуют рядом `.tar.gz.sig`. Формат подписи — 64 необработанных байта Ed25519. Подписывается сообщение `hrk-console-release-v1\n<точное имя архива>\n<sha256 архива в hex>\n`. Имя включает продукт, версию и платформу: подпись одного файла нельзя перенести на другой релиз.

Клиент сначала скачивает архив во временный файл, проверяет подпись встроенным ключом, затем распаковывает ровно ожидаемый исполняемый файл. Лимиты: архив 128 МиБ, исполняемый файл 256 МиБ. Проверяются gzip CRC, недопустимые пути, лишние файлы и неполные данные. Ошибка не меняет установленную программу. Файл для подмены сначала полностью записывается и синхронизируется во временном файле рядом с назначением.

Релизы без подписи отклоняются. Первую версию с проверкой подписи нужно установить из доверенной локальной сборки или вручную проверенного релиза: старые клиенты ещё не умеют проверять подпись. Уже выпущенные архивы автоматически подписанными не становятся.

Ключ защищает от подмены артефакта без доступа к ключу. Он не защищает от злоумышленника, который получил доступ к секрету Actions или может изменить доверенный workflow и запустить его с этим секретом. Ограничьте доступ к выпуску и сохраняйте резервную копию ключа отдельно. Смена открытого ключа требует переходного выпуска, которому доверяют установленные клиенты; не заменяйте public.key без плана миграции. Подписанный тестовый архив в selfupdate/testdata нужно обновлять при смене ключа.

## Проверки

Windows: `.\setup.ps1` устанавливает недостающие инструменты, выполняет npm ci в gui/frontend, собирает Wails и запускает тесты и vet обоих Go-модулей. Любой ненулевой код останавливает скрипт. CI также выполняет этот сценарий в Windows PowerShell 5.1.

Linux CI выполняет race-тесты и lint обоих модулей. Интеграционные SSH-тесты с настоящим ботом запускаются отдельно с HKC_TEST_REMOTE_HOST/USER/KEY/DIR; обычный тестовый прогон не обращается к вашему серверу. Тесты подписи используют локальный HTTP-сервер и подписанный тестовый архив, не GitHub.
